# 真机实时画面与控制

## 当前架构

网页选择真机并进入实时模式后显示 Loading。`device-resolve` 解析设备 UUID、
CoreDevice 隧道接口及两端地址。LayerLens 主进程加载 `libLayerLensDevice.dylib`，
协商 Apple 媒体接收和 HID 服务。

设备视频由 Apple 接收器解码为像素缓冲区，通过进程内回调交给 Swift，复用模拟器的
`LiveVideoEncoder` 和 `LiveVideoBroadcaster`。像素按有效画面裁剪、观看尺寸缩放后编码为
低延迟 H.264，经 WebSocket 发给同一套网页 WebCodecs 解码器。不再生成或解码 JPEG。
真机源帧最高 30 fps，仅保留最新源帧。协议统一为 0x01=avcC、0x02=关键帧、0x03=增量帧。
慢窗口丢弃增量帧后等待新关键帧；新窗口请求立即编码当前源帧，不重启设备采集。
首张解码画面到达后隐藏 Loading。
设备静止时可能长时间没有新解码画面，因此无帧间隔不能用于判断断流或待机，也不能据此
遮挡画面。连接故障只由原生媒体流停止、RemoteXPC 错误和 WebSocket 关闭判断；这些明确
错误会结束会话并显示重试入口，不会按无帧时长反复重建采集会话。
原生采集每秒缓存设备背光状态。触摸、按键或粘贴前若确认设备已熄屏，会先完成唤醒再发送
输入，避免首个触摸仅被系统用于唤醒而没有传到 App。视频接收器同时处理 RTP 超时、
输出失效和媒体流停止事件，这些事件才代表真实视频链路故障。
视频接收器的 stall/pause/suspend 状态会通过实时 WebSocket 转成网页上的非阻塞提示，
不会遮挡或禁用画面；重复状态不会重复提示。真机发生连接错误后，网页的“重试”会执行完整
采集重建。用户主动点击“锁屏 / 唤醒”时不执行自动预唤醒，避免唤醒后又被立刻锁屏。
真机始终按有效画面的原始分辨率编码，不再随观看窗口缩小；无效边缘填充仍会裁掉。
模拟器也始终按采集表面的原始分辨率编码。两者都保持原有编码码率和速度优先设置。

## 低延迟缓冲限制

- 编码器同时最多提交一帧，直到实际编码回调完成才释放名额。真机和模拟器源端各保留
  最新的一帧等待处理，中间画面被覆盖；模拟器重建会话时忽略旧代的完成通知。
- 每个观看窗口的应用层未完成发送包上限从 6 降为 2。超限丢弃增量帧，待发送完成后
  请求基于最新源画面生成的关键帧，不补发历史帧。尺寸变化产生的编码配置也受同一上限
  约束，只保留最新配置待发送。
- 网页解码队列达到 2 时停止提交增量帧、请求关键帧；新关键帧到达时若仍有积压，
  重建解码器并丢弃旧解码器迟到的输出。不会反复取消尚未输出的慢解码器。
- 未增加逐帧确认协议。发送完成计数不代表网页已显示，不能据此承诺端到端总缓冲
  只有两帧，也不能保证解决接收器停帧或设备断连。
点击、拖动、键盘及 Home/多任务操作通过原生 HID 通道发给设备。

同一设备多个窗口共享采集，目前同时支持一台真机。2D/3D 切换与窗口失焦保留连接；
最后一个观看连接关闭后保留 30 秒再释放。新建真机采集、已有采集接入新观看页面，以及实时页从其他模式或失焦状态恢复时，都会在原生控制队列检查背光；仅明确为 `off` 时发送一次睡眠/唤醒短按，等待背光恢复。并发恢复请求合并，普通刷新和逐帧处理不触发查询。Home 与底部小锁直接发送按键，不查询背光或密码锁定状态。模拟器使用独立的 CoreSimulator/SimulatorKit 链路。

真机与模拟器都可在目标菜单直接选择设备。默认跟随当前设备上明确在前台、可连接的
已集成 App；手动选具体 App 后仍保持跟随。设备上切到桌面、系统 App 或未集成 App，
明确确认旧 App 后台/退出且短暂等待后无其他可关联 App 时退回设备名，投屏连接不重建。
超时或未知前后台状态不推断为后台；多个前台候选有歧义时不随意选择。
左上角目标选择器旁常驻独立图钉按钮（选中 App 时显示），点击切换固定与自动跟随；
图钉使用指定的实心 SVG，未固定时灰色，固定时高亮，保留目标以查看后台或离线数据。菜单不再重复放置入口。
固定状态随当前目标保存在地址参数和本地记录，刷新或重启后保留；手动选择其他目标恢复默认跟随。
每次切换创建独立任务，立即废弃旧任务的请求、定时器和迟到结果。切换目标时保留先进入实时画面的行为；激活、就绪确认和层级读取按任务执行；2D/3D 立即切换模式，激活期间只显示当前任务的等待状态，不提前读取层级。层级最多等待 5 秒，成功、失败、超时和取消均结束 Loading。Mac 按设备串行激活，仅保留最新排队目标；窗口身份和任务顺序隔离取消操作，已发出的命令有界收尾，不终止共享设备服务。
目标菜单有 App 名称时不常驻显示 Bundle ID，完整 ID 保留在悬停提示中；完全未知名称时兜底显示 Bundle ID。
历史离线设备也可单独选择。2D、3D 和实时共用带设备图标的离线面板：选中 App 时显示
App 名称、设备断开的原因、自动恢复说明，以及查看本机日志/网络记录的入口；只选设备时
显示设备名称和重连说明，不提供 App 专属的日志/网络按钮，也不显示等待连接的 Loading。
未启动的模拟器显示“模拟器未启动”，实际启动期间显示启动状态，设备上线后自动恢复实时连接。

## 生命周期

进程关系：LayerLens → lease-guardian → Apple devicectl 隧道观察任务。
采集、解码及触摸均在主程序内，守护进程仅管理隧道观察任务的退出。

主程序独占生命周期管道写端，并设置 close-on-exec；守护进程持有读端。
正常关闭会话时关闭写端；崩溃或 SIGKILL 时系统也会关闭它。守护进程收到 EOF 后，
向自己创建的命令进程组发送 TERM，最多等待 500 毫秒，再发送 KILL，回收后退出。
不终止共享的 CoreDevice、CoreSimulator 或其他应用的进程。观察命令的 15 秒超时
保留为第二层兜底。

## 使用条件与限制

设备需已配对、信任 Mac、开启开发者模式、保持解锁，开发工具的设备支持需就绪。
实时入口不按系统版本隐藏，实际连接失败时显示原因并允许重试。
已验证上述系统组合，不代表其他系统和设备均支持。

真机仍需先解码设备视频再编码 H.264，并非原始码流透传。实际资源开销需按设备测量。
当前使用私有框架；框架异常可能影响
主程序，短时验证不等于长期稳定性保证。尚未完成全部硬件按键、键盘组合键、旋转和
长时间性能验证。

### App 状态连接共享

前后台和连接状态由 Mac 的 `TargetStateMonitor` 统一订阅现有 `/api/events`。每个设备、Bundle ID、进程实例和端口对应一条上游连接, 多个窗口共享。网页不再直接订阅各 App 的状态接口, 每个窗口只连接 `/api/hub/target-states` WebSocket。

首次连接和重连发送完整状态快照, 平时发送带会话标识、递增版本的变化。扫描负责发现和退出确认, 不能覆盖已经收到的实时通知。旧进程、旧连接和旧版本的结果会被忽略。App 退出、端口改变或设备离线时清理对应上游; 主程序退出时关闭所有状态订阅。接口返回 404 时不对同一进程反复重试, 旧 Pod 可回退到扫描的可达状态。

每个窗口最多一个发送中的消息和一份待发送的最新完整快照, 慢窗口不累积状态变化。视频、日志和抓包继续使用原有独立通道。`upstreamCount` 仅用于协议诊断, 表示当前 Mac 管理的 App 状态订阅数, 不随窗口数增加。

### 连接生命周期与空闲开销

- 前后台只依据 App 的明确通知或成功查询, 不再把扫描超时当成后台。超时仅更新可达性, 菜单可显示“响应超时”。通知带观察版本, 旧扫描不能回写; 后续成功扫描连续两次确认的矛盾状态可校正漏掉的通知。
- 状态连接握手限时 5 秒, 建立后允许长期静默。传输失败及临时 HTTP 错误按 1、2、4、8、10 秒退避, 不响应的 App 暂停新连接尝试, 恢复响应后立即重试。404 / 410 对同一进程不重试。
- 模拟器列表查询最多一个执行中, 主动刷新合并为最多一次待执行查询, 单次 5 秒超时, 必要时只强制结束该查询进程。正常查询间隔 5 秒; 查询失败保留上次列表。App 端口发现仍由 Mac 统一扫描。
- 设备、App、历史列表变化也经同一状态 WebSocket 推送, 使用独立列表版本。网页完整列表轮询降为 10 秒兜底, 并合并并发请求、丢弃在途旧快照; 恢复窗口焦点时同步一次。菜单隐藏时不重建 DOM, 展开后只在内容改变时重建。
- 确认 App 消失或设备离线后, 日志主动断开连接、关闭文件句柄, 抓包主动取消流和详情 / 正文请求; 旧任务结果不能继续修改新进程的数据。挂起但仍被发现的 App 保留已有有效流, 不反复建立连接。主程序停止发现后关闭记录器, 迟到的扫描不能重新启动订阅。
- 抓包连接每次重连均以 `since=0` 核对设备仍保留的摘要, 兼容旧 Pod 按请求 ID 回放而更新序号无序的行为, 不要求升级 Pod。Mac 按进程实例和请求 ID 合并, 完整保存的详情及正文不重复下载; 仅重连时多传摘要, 正常连接仍只推送变化。Mac 向网页的分批回放按本地更新序号排序, 保证网页增量续接不跳过未发送的页。
- 清空抓包前先原子保存设备、Bundle ID、进程实例和已清空的最大请求 ID, 再删除本机记录。重连及 Mac 重启后过滤该边界内的旧摘要, 不从设备回取已清空的详情/正文; 边界以外的新请求和其他进程/设备不受影响。对支持释放的旧 Pod 仅按 ID 释放已丢弃且结束的请求, 释放失败可重试, 不延迟执行整库清空。清空状态持久化失败时返回错误并保留现有记录; 隐藏的边界文件不随会话缓存删除。
- Mac 向网页的抓包流带本地会话版本 `epoch`。清空、进程切换、Mac 重启或冷缓存重载后版本变化; 网页重连提交 `epoch` 与已应用的 `since`, 版本不匹配时服务端先发 `clear` 再从头分批补齐, 避免错过清空事件和误用重新生成的序号。版本相同则只补变化。网页自动重连地址随已应用的记录推进, 暂停期间不确认尚未应用的页; 清空响应只触发核对, 不二次擦除响应前已经收到的新记录。此协议只涉及 Mac 与网页, 无需更新 Pod。
- 抓包状态 HTTP 查询带目标连接代数、推送观察版本和查询序号, 切换目标、收到更新推送或发起更新的查询后丢弃迟到响应。网页暂停缓冲按请求 ID 合并, 忽略更旧的重复变化, 与可见列表一致最多保留最新 5000 个请求; 恢复显示后才推进重连游标。该限制不影响 Mac 上完整的抓包保存。
- 抓包开关按目标禁止重复提交, 处理中禁用该目标的开关按钮; 切换目标后忽略旧请求的界面回写。设置响应不再替换全局目标历史, 历史由共享列表推送维护; 当前目标通过状态核对确认开关, 避免旧 HTTP 快照覆盖其他窗口或设备的新变化。
- 无人查看的离线日志及抓包缓存空闲 5 分钟回收, 各记录器使用 32 MiB 估算缓存预算并优先回收最久未使用的离线项; 活跃采集和正在查看的数据不被强制截断, 因此预算不是整个进程的内存硬上限。磁盘日志和抓包不删除, 重开时按需读回。日志恢复最多读取文件尾部 32 MiB, 同一进程恢复记录时继续追加原文件。

## 模拟器 Home 兼容

Home 每次点击经实时 WebSocket 发送一组原生按下/抬起, 由系统识别双击进入多任务。
不再使用 simctl 启动 SpringBoard。布局和独立多任务按钮不变。
按实际服务能力选择：支持 dtuhidd 时复用预热的 XPC 连接；旧版缺少服务/符号时，
使用 SimulatorKit 的 Indigo Home 按键（Xcode 26）。服务暂时失败不误判为旧版。
Home 独立队列最多接受两次待处理点击，超过 500ms 的点击丢弃并提示重试。
连接探活最多 4 秒，仅阻塞 Home 队列；关闭实时会话时取消自有连接，不停止共享服务。
协议参考 [facebook/idb](https://github.com/facebook/idb/tree/main/FBSimulatorControl/HID)。

验证：Xcode 26.6 Debug 与 Xcode 27 Release 完整编译通过；当前混合环境
（Xcode 27 CoreSimulator、Xcode 26.6 SimulatorKit、iOS 26.5）中验证 Home 双击多任务、
单击退出多任务、普通触摸打开 App。旧 Indigo 回退通过独立测试，未在纯 Xcode 26 主机上实测。

## Xcode 运行目标

运行按钮不覆盖设备 App 的前后台状态；离线后收到明确后台状态也恢复前台跟随。编译期间仍跟随同一设备上可连接的前台 App；
切换目标会停止本窗口的运行跟踪, 已交给 Xcode 的构建不会被终止。
运行前读取 Scheme 的 Run Action（含自定义配置）, 通过 xcodebuild 的已解析构建设置
核对实际 App Bundle ID 和项目路径。当前 Scheme 已匹配则保留, 否则只自动选择唯一匹配。
Scheme 歧义、无法核验的 executable、设备不支持或设置查询失败均提示错误, 不沿用其他目标。
